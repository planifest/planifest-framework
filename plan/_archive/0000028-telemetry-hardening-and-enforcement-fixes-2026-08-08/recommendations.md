## Tech Debt

| ID | Component | Description | Impact if Ignored | Suggested Fix |
|----|-----------|-------------|-------------------|--------------|
| TD-001 | `planifest-framework` | `getSessionId()` keeps 4 copies across `context-pressure.mjs`, `emit-phase-start.mjs`, `emit-phase-end.mjs` and `resolve-phase.mjs`, spanning 3 genuinely different behaviour profiles on two independent axes: a 2-priority versus 4-priority resolution chain, and whether `{cwd}/.claude/.planifest-session` is created or only read. Excluded from req-002 by name. | Low today. Each copy now carries a comment naming its profile and pointing at the others, so the trap is signposted. The risk is a future reader assuming the four are the same function, as req-002 initially did. | The before-and-after table req-002's acceptance criteria describe, over a fixed synthetic input set across all 4 callers, proving each profile survives. The req-002 snapshot harness already covers most of those fixtures. |
| TD-002 | `planifest-framework` | `readStdin()` still has 8 pre-extraction copies outside the two hook trees: `hooks/adapters/` (`cline`, `codex`, `copilot`, `cursor`, `windsurf`) and `hooks/context-mode/` (`block-bash`, `block-grep`, `block-webfetch`). | The NFR-001 fix in the shared `readStdin`, settling on a stdin stream error instead of hanging, does not reach these 8 files. They retain the shape that hangs. | Trace the adapter and context-mode install paths in `setup.sh` and `setup.ps1` the way ADR-002 traced the other three, decide the superset tree, then rewire one caller at a time under ADR-004's sequencing. Doing it unanalysed is the exact failure ADR-002 exists to prevent. |
| TD-003 | `planifest-framework` | `resolve-phase.mjs`'s `endDedupFlag()` builds `phase-end-emitted-{session}-{phase}` and sits beside the shared `get-flag-path.mjs`, which builds `phase-start-{session}-{phase}`. Neighbours, not duplicates. | Low. The risk is a future reader merging them on the assumption they are the same helper, which would break `phase_end` dedup. A comment in `get-flag-path.mjs` records why they are separate. | Leave separate. If they are ever unified, the two filename shapes and the two purposes must both survive the merge. |
| TD-004 | `planifest-framework` | The retry predicate in `emit-event.mjs` is `!(err?.name ?? "").startsWith("http_")`, which correctly excludes HTTP error statuses but also admits `AbortError`. See REC-002. | A slow but live backend can receive the same event up to 3 times. Duplicates in the governance audit trail are a records-integrity matter, not just noise. Mitigated by the envelope being byte-identical across attempts. | Either exclude `AbortError` from the predicate, or add an explicit event id to the envelope and make dedup a contract rather than the listener's choice. |
| TD-005 | `planifest-framework` | No test executes an enforcement hook through the command string `setup.sh` writes into `settings.json`. The P5 fix added a shape assertion and a bare-path pattern guard, which is not the same thing. See REC-001. | This is the exact blind spot that let SEC-001 sit undetected across 56 test suites. A future defect in the wiring that is not a bare path (a wrong relative directory, a quoting error, a missing interpreter on one branch) reproduces the same silent failure. | Parse the generated `settings.json`, take the command string verbatim, run it against a violating payload, assert exit 2 and a clean payload, assert exit 0. |
| TD-006 | `planifest-framework` | Nothing distinguishes a marker written by a hook someone invoked by hand from one written by a genuine backend failure. `recordTelemetryFailure()` derives the marker path from the process `cwd`, so any hook run from the repository root with a failing payload writes into the real `plan/.telemetry-failures/`. Three such markers carrying the fixture payload `"not json"` were found during REQ-005 and cleared by hand before verification could attribute anything. Narrowed at P6: the committed suite was re-run and does not pollute. Every 0000028 test isolates its workspace, and the five other telemetry-touching suites each left an empty marker directory empty. A related leak (a fixed `session_id` colliding on the shared OS tmpdir dedup flag) was already repaired at P3 in `6d4baf3`. | The orchestrator and `check-telemetry-failures.mjs` read that directory and surface its contents as a block-or-proceed interrupt to the human on the loop. A marker with no provenance is indistinguishable from a real failure, which is the precise interruption this feature exists to remove. | Give the marker a provenance signal rather than forbidding the write: an environment variable the harness and any manual probe set, recorded in the marker and honoured by `check-telemetry-failures.mjs`. Add a harness assertion that a full suite run leaves the repository's marker directory as it found it, so a future polluting test fails loudly instead of surfacing by hand during a verification pass. |
