# Domain Glossary - pipeline-gate-and-config-fixes-and-ship-agent-fixes

**Skill:** [spec-agent](../skills/spec-agent-SKILL.md) (updated by any agent that introduces a new domain term)
**Feature:** 0000025-pipeline-gate-and-config-fixes-and-ship-agent-fixes
**Version:** 0.1.0

> The ubiquitous language for this feature. If the glossary says "Order", the code says `Order` - not "Purchase" or "Transaction". Never invent new terms without adding them here.

## Terms

| Term | Definition | Aliases | Used In |
|------|-----------|---------|---------|
| AI-attribution footer | The hardcoded line `🤖 Generated with [Planifest](https://github.com/planifest/framework) + Claude` currently appended to every ship-agent PR description, in both the `gh pr create` body path and the human-push copy-paste template (`planifest-ship-agent/SKILL.md` Step 10). US-001 removes it by default. | attribution footer, footer line | planifest-framework |
| PR footer toggle | The undecided mechanism for whether AI-attribution-footer removal is a plain hardcoded deletion or gated by an opt-back-in file under `planifest-overrides/instructions/`. Explicitly deferred to P1/P2 to resolve with the human, per the feature brief's Deferred section. | — | planifest-framework |
| P7 archive commit | The Step 7 commit in `planifest-ship-agent/SKILL.md` that stages `plan/_archive/`, `plan/changelog/`, `docs/about.md`, and the session marker files (`plan/.orchestrator-active`, `plan/.orchestrator-ack`, `plan/.run-mode`) after P7 archiving. US-002 makes its `git add` name `plan/current/` explicitly rather than relying on git to infer the deletion side of the copy-then-delete. | archive commit | planifest-framework |
| Rename-detection heuristic | Git's default behavior of inferring a rename when a deleted file's content closely matches a newly-added file elsewhere; the P7 archive commit currently depends on this heuristic (rather than an explicit `git add`) to pick up `plan/current/`'s deletion as part of the archive-and-clear step. US-002's fix removes this implicit dependency. | rename heuristic | planifest-framework |
| Independent, non-cross-referencing writes | The qualifying condition (already used for P1 requirement files and P3 codegen, per `agent-dispatch-standards.md`'s Parallelism Rules) for dispatching writes as parallel subagent batches instead of sequentially. US-003 extends the pattern beyond P1/P3 to every phase with qualifying batches, naming P4 and P6 as the minimum additional phases. | — | planifest-framework |
| Parallel task batches | The count field already tracked per phase in `build-log.template.md`. US-003's NFR ("100% of phase batches with 2+ independent, non-cross-referencing writes dispatch in parallel") is measured against this existing field. | — | planifest-framework |
| `planifest-overrides/setup-config/` | The new versioned, committed location (one file per AI tool, e.g. `{tool}.md`) US-004 introduces for the active setup flags and backend URL, so setup configuration survives like the rest of `planifest-overrides/` instead of existing only in a gitignored marker. Does not yet exist in this repo; its first creation is part of this feature's own implementation. | setup-config file | planifest-framework |
| `.planifest-setup-flags` | The existing gitignored per-tool marker file (e.g. `.claude/.planifest-setup-flags`) written by `setup.sh`/`setup.ps1` at install time, recording `tool`, `flags`, and `backendUrl`, and read by `planifest-refresh-setup` on refresh. US-004 adds the committed `planifest-overrides/setup-config/` counterpart; on write failure setup falls back to this marker alone. | setup-flags marker, install-time marker | planifest-framework |
| Backlog pickup | The orchestrator's existing P0 step (3c, `planifest-orchestrator/SKILL.md`) that scans `plan/backlog/` entry folders and presents each one at a time for pull-in / leave / discard. US-005 is the destination this feature routes `recommendations.md`'s Deferred Items and Tech Debt entries toward, so they surface here at the next feature's P0 instead of staying buried in an archived feature's own docs. | — | planifest-framework |
| `plan/backlog/{id}-{slug}/` | The existing backlog entry-folder convention (`backlog-entry.template.md`): one folder per entry, `{id}` on its own zero-padded sequence independent of feature IDs, carrying Source feature, Source phase, and Date filed attribution. US-005 routes `recommendations.md`'s Deferred Items and Tech Debt tables into entries of this form, tagged by their source feature. | backlog entry folder | planifest-framework |
| Deferred Items / Tech Debt tables | The two tables in `recommendations.template.md`, currently produced by docs-agent at P6 and left inline in each feature's own archived `recommendations.md`. US-005 routes their rows into individual `plan/backlog/` entries instead of (or alongside) staying as tables, so they are centrally discoverable at backlog pickup. | — | planifest-framework |
| `continuous_run` | The existing session-level flag, set at P0 and persisted to `plan/.run-mode` as `continuous`, that exempts P1–P3's top-level STOP rules from stopping for confirmation (per `planifest-orchestrator/SKILL.md`'s Phase Invocation Table). US-006 extends this same exemption to docs-agent's P6 Gate B and any other phase-skill-internal gate found to share the pattern of not checking it. | — | planifest-framework |
| `plan/.run-mode` | The marker file recording `continuous` or `interactive`, written once at P0 and read by every phase to decide whether `continuous_run`'s exemption applies; deleted by the ship-agent at P9 so the next P0 always asks fresh. | run-mode marker | planifest-framework |
| Gate B | `planifest-docs-agent`'s P6 checkpoint ("assess whether a docs update is needed," distinct from Gate A's `docs/` existence check) that currently always stops for human confirmation regardless of session state. US-006 is the specific defect: Gate B does not check `continuous_run` before stopping, unlike the orchestrator's top-level P1–P6 STOP rules. | — | planifest-framework |
| Internal confirmation gate | The general pattern name for a phase-skill-owned STOP, like Gate B, that lives inside a phase skill's own logic rather than the orchestrator's top-level P1–P6 STOP rule table, and can therefore independently forget to check `continuous_run`. US-006 requires auditing other phase skills (spec-agent, adr-agent, codegen-agent, etc.) for this same pattern and fixing any found. | — | planifest-framework |
| Scope Lock Challenge | The mandatory P0 gate (`planifest-orchestrator/SKILL.md`) run after coaching Q&A and before design confirmation: four scenario-path questions (happy path, first-run path, error/sad path, cross-session continuity) asked one at a time, each carrying a suggested-answer offer. Currently a suggested answer is drafted only on explicit human request, per `0000017-ADR-003`. US-007 changes the default to always draft all four answers up front and present them together for one batch accept/edit/reject pass. | — | planifest-framework |
| Scenario-path answers | The four answers produced by the Scope Lock Challenge — happy path, first-run path, error/sad path, cross-session continuity. US-007 changes how they are produced: from individually-offered-and-drafted-only-on-request, to always-drafted-in-parallel-and-batch-presented. | — | planifest-framework |
| Draft-and-batch flow | US-007's new default Scope Lock Challenge behavior: draft all four scenario-path answers up front via parallel `planifest-scope-lock-agent` dispatch, then present them together for a single accept/edit/reject pass — replacing the current four sequential opt-in round-trips. If one of the four parallel drafts fails, the other three are presented with a clear failure marker for the fourth, which falls back to the original blank-question flow for that item only. | — | planifest-framework |
| `planifest-scope-lock-agent` | The existing subagent that drafts a single suggested Scope Lock Challenge answer, currently spawned only on explicit human request for one question at a time. US-007 changes its trigger to default-on and its dispatch to four-way parallel (one subagent per scenario path, in the same message). | — | planifest-framework |
| `0000017-ADR-003` | The existing ADR ("Scope Lock Suggested Answers via On-Demand Subagent") recording today's on-request-only Scope Lock Challenge behavior. US-007's draft-and-batch default directly reverses it; a new ADR superseding it is produced at P2. | ADR-003 | planifest-framework |
| `0000014-ADR-008` | The existing ADR ("One-Question-at-a-Time as Framework-Wide Instruction") establishing the framework-wide one-question-at-a-time convention. US-007's batch-presentation change touches this convention for the Scope Lock Challenge specifically; the new superseding ADR must scope the change narrowly so it does not read as a silent framework-wide reversal of `0000014-ADR-008`. | ADR-008 | planifest-framework |
| Downstream adopter | A separate project that has run Planifest's setup against this canonical `planifest-framework` repo and files friction/backlog items back against it, rather than only against its own local copy. Concretely: the "telemetry-mcp" product repo, which filed backlog entries 0000040 and 0000041 — the items that directly inform US-006 (docs-agent `continuous_run`) and US-007 (Scope Lock defaults). | — | planifest-framework |
| Backlog entry | An item filed at `plan/backlog/{id}-{slug}/entry.md` per `backlog-entry.template.md`: Problem, Suggested Action, and Why Deferred, with Source feature/Source phase/Date filed attribution, on its own ID sequence independent of feature IDs. US-005's routing target for `recommendations.md`'s Deferred Items and Tech Debt rows; an entry missing its source attribution is flagged to the human as malformed, never silently ignored or parsed as instructions. | — | planifest-framework |
