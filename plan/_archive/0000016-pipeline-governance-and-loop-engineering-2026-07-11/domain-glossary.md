## Terms

| Term | Definition | Aliases | Used In |
|------|-----------|---------|---------|
| Backlog entry | One folder under `plan/backlog/{id}-{slug}/` recording a discovered-but-out-of-scope item: problem, source feature/phase, date filed | — | planifest-framework |
| Pickup | The P0 act of presenting each backlog entry to the human (pull-in / leave / discard), one at a time | backlog pickup | planifest-framework |
| Product manifest | `product.yml` at project root aggregating one release version across components | product.yml | planifest-framework |
| Version policy | The `versionPolicy` field: how the product version is derived — `max-component-version`, `explicit`, or `external` | versionPolicy | planifest-framework |
| Wave | A feature-decomposition group within one feature brief (formerly "Phase" in that sense; renamed to avoid P0–P9 collision) | — | planifest-framework |
| Loop | A bounded iterate-until cycle inside a pipeline phase: act → observe → record → decide, with armed stop rules | agentic loop | planifest-framework |
| Loop state | The git-tracked file in `plan/current/` holding a loop's iteration counter, cap, budget counters, and escalation context | loop-state file | planifest-framework |
| Run log | Append-only record, one structured entry per loop iteration: action, observation, decision (continue/done/escalate) | loop run log | planifest-framework |
| Stop rule | A deterministic loop exit condition: iteration cap, or no-progress detection (same gap/finding across 2 consecutive iterations) | — | planifest-framework |
| Toggle | Per-loop setting `off \| report-only \| on`; every loop defaults `off` | loop toggle | planifest-framework |
| Report-only | Toggle level where a verifier runs and files findings but blocks nothing and mutates nothing | — | planifest-framework |
| Maker–checker separation | Control principle: the agent that produced work never judges it; verifiers run as fresh-context subagents | maker-checker | planifest-framework |
| REJECT-default | Verifier stance: approval requires explicit positive evidence; absence of objection is not approval | deny-by-default | planifest-framework |
| Defect report | Structured artifact filed by a blocked P3–P6 agent naming the binding upstream artifact, attempts, and evidence | design-defect report | planifest-framework |
| Reversal | A granted, scoped correction of an upstream P0–P6 artifact triggered by a defect report | phase reversal | planifest-framework |
| Reversal budget | Hard cap of 2 granted reversals per feature, persisted in loop state, surviving resume | — | planifest-framework |
| Invalidation cascade | The traceability-derived list of downstream artifacts a reversal's revision actually invalidates — only these are re-done | cascade | planifest-framework |
| Revision log | `plan/current/revision-log.md`: one entry per rev-bumped artifact (artifact, old→new version, defect reference, date) | — | planifest-framework |
| Altering (reversal class) | A reversal that changes what the human confirmed at the design gate — voids continuous-run authorization | vs. additive | planifest-framework |
| Ratchet | The rule (enforced by `ratchet-check.mjs`) that loops may strengthen criteria/scope but any weakening requires explicit human approval | ratchet rule / ratchet hook | planifest-framework |
| Reward hacking | Failure mode where an agent passes a check by weakening it instead of doing the intended work — the ratchet's target | — | planifest-framework |
| Verify-by-execution | Verifying an acceptance criterion by running the software and observing behaviour, never by reading test output alone | — | planifest-framework |
| Cross-model review gate | Pre-P7 gate where a fresh-context reviewer on a different model id approves the diff, REJECT-default, capped loop | — | planifest-framework |
| Phase gate | The existing per-phase STOP/confirm boundary in P0–P9 (distinct from Wave and from loop stop rules) | — | planifest-framework |
