## Context

REQ-004 requires the orchestrator to produce a skill-to-requirement mapping showing which Planifest skill is best suited to implement or verify each functional requirement. This mapping must be:
- Produced at P0 end
- Re-evaluated at each phase gate
- Visible to the human for confirmation before each phase proceeds
- Persistent across session boundaries (so it can be re-evaluated on resume)

A decision is needed about where to store this mapping.

---

## Decision

The skill map is stored as a `## Skill Map` section appended to `plan/current/design.md`. Design.md is already the single confirmed-design document read by all agents at phase start. Adding the skill map there means:
- All agents already read design.md; no additional file load is needed
- The map is co-located with the design it derives from
- Gate-write already permits writes to design.md (it is in `plan/`)
- Resume detection already reads design.md; the skill map is automatically restored on resume

---

## Alternatives Considered

| Alternative | Pros | Cons | Why Rejected |
|-------------|------|------|-------------|
| Separate file (`plan/current/skill-map.md`) | Clear separation of concerns; design.md stays focused on architecture | Another file for agents to load; resume detection must be updated to also read it; potential for drift between design and skill map | Adds file proliferation without meaningful benefit; design.md already plays this aggregating role |
| In the execution plan (`plan/current/execution-plan.md`) | Near requirements; spec-agent already owns execution-plan | Execution plan is produced in P1; skill map is produced in P0 (before P1); wrong phase ownership | Phase timing mismatch |
| In the build log | Already updated per phase | Build log is telemetry, not a planning artifact; not read by phase agents | Wrong artifact type |
| In memory only (not persisted) | No file changes | Lost on session end; not available to human for review; cannot be re-evaluated on resume | Violates the persistence requirement |

## Affected Components

| Component | Impact |
|-----------|--------|
| planifest-framework | Orchestrator SKILL.md updated to produce and maintain `## Skill Map` section in design.md; design.template.md updated to include the section |

---

## Consequences

**Positive:**
- Zero additional files; human has one document to review for both design and skill routing
- Agents already read design.md — skill map is free context
- Map survives session boundaries without additional resume logic

**Negative:**
- Design.md grows slightly with each feature (skill map section added to a document that is otherwise concise)
- Skill map may become stale if requirements change mid-pipeline and the orchestrator misses a re-evaluation; mitigated by gate protocol

**Risks:**
- If design.md grows large (many requirements, large skill map), agents reading it in full may consume notable context; mitigated by Planifest's existing guidance to keep features small and phased
