## Terms

| Term | Definition | Aliases | Used In |
|------|-----------|---------|---------|
| Refresh | Re-running `setup.sh`/`setup.ps1` for an already-installed tool with the flags currently in effect, without the human having to re-specify them | "re-run setup", "refresh the framework setup" | `planifest-refresh-setup` |
| Reconstruction | The process of determining which setup flags are currently active by reading installed hook wiring and/or the flags-used marker file | "flag reconstruction", "detection" | `planifest-refresh-setup` |
| Confidence level | A per-flag rating (high / medium / low) reflecting how directly an installed-state signal maps to the flag it implies; high when read from the marker file, variable when inferred from hook wiring | "confidence report" | `planifest-refresh-setup` |
| Flags-used marker | `.claude/.planifest-setup-flags`, the single file that both records the flags used at install time (written by `setup.sh`/`setup.ps1`) and serves as the refresh skill's retry/recovery cache | "marker file", "setup flags marker" | `setup-hook-integration`, `planifest-refresh-setup` |
| Boot files | `CLAUDE.md` and `AGENTS.md`, the only two files the refresh skill is ever permitted to delete, because `setup.sh`/`setup.ps1` will not regenerate them if they already exist | "regenerable boot files" | `planifest-refresh-setup` |
| Deletion allowlist | The hardcoded, non-extensible set of files (boot files only) the refresh skill may delete | "allowlist" | `planifest-refresh-setup` |
| Human on the loop | The person operating the agent session; the only party who can confirm a reconstructed flag set before any destructive action | "operator" | `planifest-refresh-setup`, framework-wide term (see `CLAUDE.md`) |
| Uncompleted attempt | The marker-file state (`attemptStatus: pending`) written by the refresh skill before deletion begins and before setup reports success; signals an in-progress or interrupted refresh | "pending attempt" | `setup-hook-integration`, `planifest-refresh-setup` |
